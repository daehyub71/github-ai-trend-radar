### 1-2. 신호별 결론

**S2 포크 — 포크 목록 소급은 쓰지 않는다 (제안)**
- 목록 1쪽(100개)에 평균 약 2.3초(REST 461회 1,071초). 표본의 8/20이 30쪽(3,000개)을 읽고도 12주 전까지 닿지 못했다.
- 후보 200개를 소급하면 포크만으로 수 시간이 걸리고, 큰 저장소일수록 끝까지 못 간다 — 소급 결과가 저장소 크기에 따라 달라진다(편향).
- 포크 11만 개인 morluto/rea 는 3쪽 만에 목록이 끝났다. API 가 포크 목록을 다 주지 않는 경우가 있다.
- → 주간 실행은 저장소 메타 `forks_count` 를 매주 저장해 차이를 낸다(호출 1회). 12주 소급 구간의 S2 는 **결측**(지수에서 빼고 재분배)으로 둔다.

**S3 기여 — 12주를 질의 한 번으로 받아 주별로 나눌 수 있다**
- 결과마다 `merged_at`·`closed_at` 이 있어 주별로 나눌 수 있다. 저장소당 PR·이슈 각 1질의(+쪽), 평균 8질의, Search 160회 236초.
- 1,000건 상한을 넘은 저장소 5/20(PR 기준) — 이런 저장소는 **기간을 주 단위로 쪼개 다시 질의**한다.
- 봇 PR 은 저장소마다 크게 다르다(getpaseo/paseo 443건). 봇 제외는 필수.
- 추정: 후보 200 소급 ≈ Search 1,600~2,000회 ≈ 분당 30회 기준 55~70분. 주간 실행(1주 창)은 저장소당 2~3질의 ≈ 15~20분.

**S4 사용 — 이름 조회로는 연결률이 낮다 (판단 필요)**
- 저장소 이름으로 PyPI·npm 을 조회하고 패키지의 저장소 URL 이 일치할 때만 쓰는 방식(star-trend 와 같음)으로 **20개 중 2개(10%)**만 연결됐다.
- 표본의 절반 이상이 에이전트 스킬·앱이라 패키지가 원래 없다. 패키지가 있을 법한 ComfyUI·ollama 도 이름 조회로는 찾지 못했다(ollama 는 Go, PyPI `ollama` 는 다른 저장소).
- 연결된 두 개의 패키지 의존 수는 0(ecosyste.ms 가 아직 집계하지 않음).
- pypistats 는 2026-04-08 부터 일별 이력이 있어 12주 소급은 된다. npm range 도 된다.
- → 가중치 30 인 신호가 대부분 결측이 된다. 대응은 §2 판단 사항.

**S5 언급 — HN 은 소급되지만 신호가 드물다, GeekNews 는 소급 가능**
- HN Algolia 기간 검색으로 12주 소급이 된다(저장소당 1회, 평균 0.55초). URL 정확 일치 글이 있는 저장소는 8/20, 대부분 점수 1~7점.
- GeekNews `/past?day=` 는 1년 전(2025-11-09)까지 읽힌다. 하루 12~20개 글, 깃허브 링크는 하루 2~6개.
  12주 소급 ≈ 84일 × 1~2쪽, 요청 간격 2초 → 약 3~6분.
- robots.txt 는 모델 학습용 크롤러(ClaudeBot 등 이름 지정)만 막고 검색·사용자 요청 조회는 허용한다. 우리 요청은 이름 지정 대상이 아니고 `/past` 는 막혀 있지 않다. 요청 간격 2초를 지킨다.
- → P3: GeekNews 를 **주간·소급 모두 포함**(제안). 다만 S5 는 대부분 0 이라 백분위 동점이 많다 — M2 에서 결측률과 함께 본다.
